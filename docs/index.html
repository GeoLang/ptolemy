Features

🔀 Versioned Geodata

  • Git-like branching & merging for features
  • Full changeset history with diffs
  • Branch-level isolation for concurrent edits
  • Conflict detection & resolution
  • Time-travel queries (any revision)

🗄️ PostGIS Backend

  • PostgreSQL + PostGIS for spatial indexing
  • A GIST-indexed geometry column and a JSONB properties column per feature version
  • Spatial queries (intersect, within, buffer)
  • Full ACID transactions
  • Connection pooling (sqlx)

🌐 REST API

  • Axum 0.8 async HTTP server
  • Dataset, branch, and feature CRUD
  • Commit endpoint with DiffOp operations
  • Branch merge with conflict reporting
  • Diff between any two changesets
  • Branch history (commit log)
  • Spatial queries (bbox, intersects, within)
  • MVT vector tile endpoint
  • Cursor-based pagination
  • Batch commit operations
  • Health checks & readiness probes
  • A body or query string naming a field the route does not declare is refused, 422 or 400, with the key named

🤝 Collaboration

  • Multi-user concurrent editing
  • Named branches per team/task
  • Review & merge workflows
  • Three-way merge with conflict detection
  • Authenticated workspaces and nested projects
  • Owner, editor, and viewer roles with inherited access
  • Expiring workspace and project invitations
  • Invitations grant editor or viewer and require an authenticated acceptance
  • A dataset attached to a project is private to its members, at their project role
  • Roles do not reach Agora permissions
  • Ephemeral room relay (view sync, cursor sharing, chat)
  • Follow mode — sync camera between viewer instances

📐 Geospatial Types

  • Point, LineString, Polygon, Multi-*
  • Arbitrary JSON properties per feature
  • Schema-on-read flexibility
  • UUID v7 for time-ordered IDs
  • WKB/GeoJSON interchange

🚀 Deployment

  • Single binary CLI (ptolemy serve)
  • Docker + docker-compose
  • ENV-based configuration
  • GeoJSON import/export
  • Full CLI: dataset, branch, commit, merge, log, diff
  • Prometheus metrics endpoint (/metrics)
  • Graceful shutdown (SIGTERM/SIGINT)
  • Configurable connection pool

🔐 Authentication

  • JWT authentication (PTOLEMY_JWT_SECRET)
  • Workspace and project roles: owner, editor, viewer
  • Project access inherited from workspace membership
  • Direct project membership for project-only access
  • A dataset attached to a project is reached by its members: viewer reads, editor writes, owner administers
  • OIDC Single Sign-On against Keycloak: the three endpoint URLs are built from the issuer as /protocol/openid-connect/…, so a provider that spells them differently does not work
  • Token exchange & user info retrieval
  • Per-endpoint permission checks

📏 Schema & Topology

  • Dataset schema definitions (field types). Stored, not enforced
  • PostGIS Topology primitives (faces, edges, nodes)
  • Auto-repair invalid geometries (ST_MakeValid)

📡 Webhooks & CDC

  • Subscribe a url per dataset, filtered by event type
  • commit, merge, branch_created, schema_changed, plus custom events
  • HMAC-SHA256 signed delivery, retried with a backoff, five attempts
  • Events are queued in the commit's own transaction, so a restart loses none
  • The worker also deletes settled deliveries and the events behind them, hourly, after PTOLEMY_EVENTS_RETENTION_DAYS

📊 Spatial Analytics

  • Buffer analysis (per-feature, configurable distance)
  • Union analysis (aggregate geometry)
  • Coverage: the area a branch's features reach when buffered, counted once where they overlap
  • DBSCAN spatial clustering
  • Anomaly detection (outliers, self-intersections)
  • Branch-level spatial statistics

🌍 OGC Compliance

  • OGC API - Features 1.0 Core
  • GeoJSON feature collections
  • Bbox filtering, pagination
  • Conformance declaration
  • Part 2 CRS by reference: CRS84, EPSG:4326, EPSG:3857 and the dataset srid
  • CRS84 is longitude first, a geographic EPSG code latitude first

ArcGIS FeatureServer

  • Every dataset is a single-layer FeatureServer under /arcgis/rest/services, so Esri clients connect unchanged
  • query takes the SQL-92 where subset those clients send, paging, outSR/inSR, an envelope filter and f=json, pjson or geojson
  • returnDistinctValues, outStatistics with groupByFieldsForStatistics, and having over the same seven functions
  • applyEdits lands the whole batch as one commit on main, or refuses all of it
  • Attachments, and extractChanges deltas against a generation the client holds
  • A stored Esri drawing document is served back as drawingInfo, or translated to Mapbox GL layers at /api/v1/datasets/{id}/style
  • A token may arrive in X-Esri-Authorization or a token parameter, read under this prefix and nowhere else

Your existing PostGIS, read-only

  • Register a table or view as an external dataset and read it through the normal API without copying it
  • Feature listing, bbox, CQL2, OGC items, GeoJSON and CSV export, vector tiles
  • Commits, merges, imports, QGIS push and branch creation answer 409
  • Geometry is served in EPSG:4326, and spatial reads also push an index-served predicate onto the relation's own column in its own SRID
  • An ordinary GiST index on the geometry column is all it needs
  • PTOLEMY_EXTERNAL_DATABASE_URL points this at a second database, where a SELECT-only role makes the read-only part PostgreSQL's job

🔎 Audit Log

  • One row per mutation: subject, route, target, time
  • Reads are not recorded
  • Read back at GET /api/v1/audit, instance admin only

⏱️ Temporal Queries

📂 Data Catalog

  • Tag-based organization & filtering
  • Rich metadata (source, license, attribution)
  • No ranking and no typo tolerance: it is ILIKE, not a text index

Access

Operations

  • Prometheus metrics at /metrics for an admin token
  • No trace export. There is no OTLP exporter in the binary

Architecture

ptolemy-core

  • Domain types: Dataset, Branch, Changeset, Feature, Diff
  • Serialization with serde
  • WKB and GeoJSON conversion through geozero
  • The DataStore trait a backend crate implements

ptolemy-storage

  • PgStore, the one store the server and CLI use
  • SQL migrations, run on every serve
  • Reads and writes go through a Reader or Writer that carries the permission decision

ptolemy-geopackage / -mongodb / -elasticsearch

  • Each implements the DataStore trait from ptolemy-core
  • No binary depends on them: the server and the CLI use PgStore
  • The CLI reads shapefiles and writes GeoPackage itself, through shapefile and rusqlite

ptolemy-api

  • Axum 0.8 HTTP router
  • Layers: tracing, auth, dataset visibility, the write gate, audit, metrics
  • Permissive CORS on the ArcGIS routes, which real ArcGIS servers answer, and nowhere else
  • Typed JSON responses

ptolemy-cli

  • Clap-based CLI
  • ptolemy serve --bind 0.0.0.0:3000
  • Dataset, branch, commit, merge, import, export, backup commands

Real-Time Collaboration Relay

Ptolemy includes an ephemeral room-based WebSocket relay at /ws/rooms/{room_id} for real-time viewer collaboration. Every JSON message sent by one participant is broadcast to all others in the same room. No messages are persisted — rooms are created on first connection and dropped when the last client disconnects.

📡 View Sync (Follow Mode)

  • Broadcast camera state (lat, lng, zoom, bearing, pitch)
  • Follower's viewer mirrors the leader's view in real-time
  • The server relays every frame it is given, so throttling is the client's job

🖱️ Cursor Sharing

  • Share mouse position on the map between collaborators
  • See other users' cursors as coloured dots

👥 Presence & Chat

  • Track which users are online in a room
  • User name and colour assignment
  • Real-time text messaging within a room

Protocol (JSON over WebSocket)

// Connect to a room. The handshake needs a token, and a browser cannot set
// the Authorization header on a WebSocket, so it goes in the subprotocol:
// new WebSocket("ws://localhost:3000/ws/rooms/my-room", ["bearer", jwt])
ws://localhost:3000/ws/rooms/my-room

// Client → Server (relayed to every other client in the room, never back to the sender)
{ "type": "Join",   "user_id": "u1", "user_name": "Alice", "asset_id": "my-room" }
{ "type": "Camera", "user_id": "u1", "latitude": 40.7, "longitude": -73.9, "zoom": 14, "bearing": 0, "pitch": 45 }
{ "type": "Cursor", "user_id": "u1", "latitude": 40.71, "longitude": -73.91 }
{ "type": "Chat",   "user_id": "u1", "user_name": "Alice", "message": "Look at this area" }
{ "type": "Leave",  "user_id": "u1", "asset_id": "my-room" }

Messages are opaque to the server — it relays any valid text frame to all other subscribers. The schema above is the convention used by ViewTopia's collaboration client.

Quick Start

# Clone and build
git clone https://github.com/GeoLang/ptolemy.git
cd ptolemy
cargo build --release

# Start with a PostGIS database. serve refuses to start without a signing
# secret of 32 bytes or more, and applies migrations before it binds.
export DATABASE_URL="postgres://user:pass@localhost/ptolemy"
export PTOLEMY_JWT_SECRET="$(openssl rand -hex 32)"
./target/release/ptolemy serve --bind 0.0.0.0:3000

# Check health
curl http://localhost:3000/api/v1/healthz
curl http://localhost:3000/api/v1/readyz
